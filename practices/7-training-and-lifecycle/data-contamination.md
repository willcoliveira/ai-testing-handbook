# Data contamination

## What
Data contamination is evaluation data reaching training data, so a score measures memory instead of capability. Xu et al. define benchmark data contamination as what "occurs when language models inadvertently incorporate evaluation benchmark information from their training data, leading to inaccurate or unreliable performance during the evaluation phase" [S155]. It applies to a public benchmark scraped into a pre-training corpus and equally to a team's own golden set pasted into a fine-tuning file or a prompt. This page covers how it happens, how it is detected, and how to keep a private set clean.

## Why
GSM1k is the cleanest demonstration. Scale AI wrote 1,205 grade-school maths problems by hand, with no LLM in the loop, matched to GSM8K's difficulty and answer distribution, and kept them private. Several open model families scored up to 8 points lower on GSM1k than on GSM8K: "Phi, Mistral and some models in the Llama family seem to be overfitting GSM8k", while "Models such as Gemini, GPT, and Claude show little to no signs of overfitting" [S154]. A model's likelihood of generating GSM8K examples correlated with its gap (Spearman r² = 0.36), which is the contamination signal, but outliers show "overfitting on GSM8k is not purely due to data contamination, but rather may be through other indirect means, such as model builders collecting data similar in nature to benchmarks" [S154]. The trade-off: a private set cannot be audited by outsiders and goes stale; a public set is auditable and gets absorbed. Xu et al. conclude "it is deemed impracticable to fully remove the risks associated with contamination" [S155].

## How
1. **Name the level.** Xu et al. distinguish semantic level (identical or derivative content), information level (benchmark-related information that biases the model), data level (inputs without labels) and label level (inputs with labels) [S155]. Say which one you are checking for; an n-gram scan finds only the last two.
2. **Detect with more than one method.** Matching-based: n-gram overlap (13-gram for GPT-3 and 50-character for GPT-4 in the survey; Llama 3 reports 8-gram overlap between benchmarks and training data), membership inference, dataset inspection and example generation. Comparison-based: perplexity or likelihood on the eval set, ordering tests, and chronological analysis, where "Model performance is gauged on a dated dataset" released after the training cutoff [S155] [S143].
3. **Measure the gap, not the score.** Build a mirror set with the GSM1k recipe: human-written, no model assistance, matched difficulty and answer distribution, three review layers, and compare the public-set score with the mirror-set score per model [S154]. A gap larger than the run-to-run spread is the finding.
4. **Keep your own set private and off the wire.** The golden set never goes into a fine-tuning file, a prompt example, a public repository or a provider that trains on inputs. Date-stamp every case with the model cutoff in force when it was written, so a chronological check is possible later [S155].
5. **Decontaminate before training.** Run the n-gram check between the fine-tuning data and every eval set before the job; Llama 3 states "We do not include any training sets from commonly used benchmarks in our annealing data" [S143]. See [fine-tuning-evals](fine-tuning-evals.md).
6. **Refresh on a rule.** GSM1k committed to release when "the top open source models score over 95% on GSM1k or 2) June 2025, whichever comes earlier"; write a similar rule for retiring cases from your private set and writing new ones [S154].
7. **Prefer benchmark-free checks where they fit.** The survey groups judge-based and human-comparison evaluation, dynamic benchmarks and regenerated prompts as mitigations; each has its own bias, see [llm-as-judge](../3-judging/llm-as-judge.md) [S155].

| Signal | What it shows | Misses |
|---|---|---|
| n-gram overlap | verbatim copies in a corpus you can read [S143] [S155] | paraphrase, translation, closed corpora |
| likelihood of eval examples | memorisation without reading the corpus [S154] | indirect similar-data overfitting |
| public versus mirror gap | overfitting from any cause [S154] | requires writing a mirror set |
| dated set after cutoff | contamination by time [S155] | difficulty drift across time |

Hygiene rules for a team's private set, each traceable to the sources above:

| Rule | Reason |
|---|---|
| Written by people, not generated by the model under test | GSM1k used "No language models" so the set could not echo a model's training distribution [S154] |
| Never stored where training jobs read | data-level and label-level contamination start with one copy [S155] |
| Split by date of authorship | enables a chronological check when the next model ships [S155] |
| Public-set score always reported next to the private-set score | the gap is the finding, not either number [S154] |
| Retire-and-replace rule written down | a private set ages into the next model's training era [S154] |

## Who does it (sourced)
- **Xu, Guan, Greene and Kechadi, 2024-06-06:** a survey defining benchmark data contamination, a four-level taxonomy, matching-based and comparison-based detection, and mitigation by data curation, data refactoring and benchmark-free evaluation [S155].
- **Scale AI, 2024-05-01 (v4 2024-11-22):** GSM1k, "created using human annotators" with "No language models", held private, drops of up to 8 points, Spearman r² = 0.36 between GSM8K likelihood and the gap [S154].
- **Meta, 2024-07-31:** Llama 3 excludes benchmark training sets from annealing data and reports an 8-gram overlap contamination analysis [S143].
- **DeepSeek, 2026-01:** the R1 arXiv v2 refers to a pre-training decontamination procedure in an appendix and states that web pages containing OpenAI-model-generated answers were present without the team intentionally adding synthetic OpenAI data [S153].
- **ByteDance Seed, 2025-08:** the Seed-OSS card states that ARC-AGI-2 was "measured on the official evaluation set, which was not involved in the training process", and ships base variants with and without synthetic instruction data because their inclusion "may affect post-training research" [S231].
- **Alibaba Qwen, Moonshot AI, Zhipu, 2025 to 2026:** the Qwen3, Kimi K2, Kimi K2.5, GLM-4.5 and GLM-5 reports contain no contamination or decontamination check; treat their scores accordingly [S220][S224][S225][S229][S230].
- **AI2, December 2025:** the `decon` tool detects n-gram matches and expands them into clusters before removing documents; it targets midtraining "in light of results suggesting that memorization occurs most strongly near the end of training" [S278].
- **Cohere, April 2025:** extends its "uncontaminated" LBPP benchmark to five more languages and curates human-evaluation prompts from scratch to avoid contaminating competitor comparisons [S272].
- **EleutherAI, August 2026:** shipped a fix for "Eval documents leaked into few-shot prompts" in the harness itself [S274].
- **arXiv, 2026-08:** a taxonomy of contamination organised by which mitigation each type defeats, with a disclosure protocol for reporting contamination status beside a score [S301].
- **arXiv, 2026-09:** a synthetic-data screen for training corpora that measures lexical-diversity collapse and n-gram tail truncation [S304].
- **arXiv, 2026-08:** residual-stream probing for contamination carried more variance than its baseline and gave no definitive verdicts, so activation probes are not reliable detectors [S305].

## Pitfalls
1. **N-gram as the only check.** It finds verbatim copies; paraphrased and translated copies pass [S155].
2. **Low overlap read as no overfitting.** GSM1k's outliers overfit without high likelihood scores; "small amounts of data contamination do not necessarily lead to overfitting" and the reverse also holds [S154].
3. **Training on data "similar in nature".** Not contamination by definition, still a gap on the mirror set [S154].
4. **The private set that ships.** One paste into a fine-tuning file or a prompt example ends its life as a held-out set [S155].
5. **A private set that never refreshes.** Without a release-and-replace rule it silently ages into the training era of the next model [S154].
