# Knowledge matrix

One row per sub-area of the [taxonomy](../TAXONOMY.md): the concept in a line, a worked example,
how a tester tests it, the tools, and the practice that owns it. Use it as a checklist or as a
question bank.

| Area | Concept | Worked example | How a tester tests it | Tools | Practice |
|---|---|---|---|---|---|
| 1 Capability | Public benchmarks measure a model on a fixed task set with a fixed grader | a coding benchmark graded by hidden unit tests | reproduce one score with the published harness; note the error bar | Inspect, HELM, lm-eval | [capability-benchmarks](../practices/1-capability/capability-benchmarks.md) |
| 1 Capability | A score without an error bar is not a number | two models 1.5 points apart on 500 questions | compute a confidence interval; test the paired difference | any stats library | [statistical-treatment-of-evals](../practices/1-capability/statistical-treatment-of-evals.md) |
| 1 Capability | Contamination and leaderboard gaming inflate scores | a benchmark whose test set is on the web | check publication dates against training cutoffs; prefer private or rolling sets | benchmark cards | [benchmark-hygiene](../practices/1-capability/benchmark-hygiene.md) |
| 2 Application | Evals are the unit tests of a prompt-and-model system | a support bot with 200 labelled tickets | run the set on every prompt change; fail on regression | promptfoo, DeepEval, Braintrust | [eval-driven-development](../practices/2-application-evals/eval-driven-development.md) |
| 2 Application | A golden set is sampled from reality and held out | 200 items sampled from traces, 50 hidden | audit label quality; freeze the held-out split; document it | dataset cards, datasheets | [golden-datasets](../practices/2-application-evals/golden-datasets.md) |
| 2 Application | A criterion is a behaviour, not a phrase | "confirms the spelling before continuing" | rewrite phrase-locked criteria; rerun after a prompt change | criteria guide | [criteria-authoring](../practices/2-application-evals/criteria-authoring.md) |
| 2 Application | One run is a sample; gate on the distribution | 10 runs, 9 of 10 required | run N times; alert on shift between versions; pin model and prompt | batch runners | [non-determinism-and-pass-rates](../practices/2-application-evals/non-determinism-and-pass-rates.md) |
| 2 Application | Per PR, nightly, manual: each gate earns its place | a one-user stubbed smoke per PR | never gate what fails every run; write the reason next to the threshold | CI, k6 | [ci-gates-for-llm-apps](../practices/2-application-evals/ci-gates-for-llm-apps.md) |
| 2 Application | Model-adjacent code can be tested without a model | list rendering across every configuration pair | drive the real functions against the real config; no mocks | pytest, a probe script | [offline-probes](../practices/2-application-evals/offline-probes.md) |
| 3 Judging | A model can grade prose, with known biases | a judge marking pass, fail, unable to verify | position swap; length control; calibrate against humans | judge prompts, Langfuse evaluators | [llm-as-judge](../practices/3-judging/llm-as-judge.md) |
| 3 Judging | Judge agreement with humans is measured, not assumed | 300 human labels, kappa reported | sample, label, compute agreement, recalibrate on prompt change | annotation tools | [judge-calibration](../practices/3-judging/judge-calibration.md) |
| 3 Judging | Human labels need a process | two graders read the same evidence | resolve disagreements; require evidence even for passes | labelling tools | [human-annotation](../practices/3-judging/human-annotation.md) |
| 3 Judging | Binary beats Likert; pairwise beats absolute for preference | A versus B with swapped positions | write binary rubrics; use pairwise for style, absolute for correctness | evaluation harnesses | [rubrics-and-pairwise](../practices/3-judging/rubrics-and-pairwise.md) |
| 4 Agents | Assert on outcome and state, not on transcript | the database row after the agent finishes | check state, side effects and the trajectory | tau-bench style evals | [agent-evals](../practices/4-agents-and-systems/agent-evals.md) |
| 4 Agents | A harness runs tasks, scorers and models reproducibly | a suite of 50 tasks with two scorers | pick one; keep tasks and scorers in version control | Inspect, promptfoo, DeepEval | [harnesses](../practices/4-agents-and-systems/harnesses.md) |
| 4 Agents | A simulated user is a second probabilistic system | five personas against a voice agent | measure the simulator's noise floor first; set a stability gate | simulators, agent-to-agent platforms | [orchestrators-and-simulators](../practices/4-agents-and-systems/orchestrators-and-simulators.md) |
| 4 Agents | Tool calls are an API and test like one | schema, auth scope, idempotency on mutation | contract tests with no model; trajectory assertions | BFCL, contract tests | [tool-use-evals](../practices/4-agents-and-systems/tool-use-evals.md) |
| 4 Agents | Voice adds speech, timing and audio to everything above | barge-in during a read-aloud list | text harness for logic; real calls for audio; relay frames for timing | Twilio relay, developer phone | [voice-agent-testing](../practices/4-agents-and-systems/voice-agent-testing.md) |
| 4 Agents | A load test proves turn-taking, not quality | a virtual user is one call | stub the model, keep integrations; gate the median; read answers back | k6 | [load-and-latency](../practices/4-agents-and-systems/load-and-latency.md) |
| 4 Agents | Exploration finds what the suite does not | a 45-minute charter against a chat surface | evidence per claim; one bug one report; severity lower when in doubt | Claude Code skills, Playwright | [exploratory-testing-of-agents](../practices/4-agents-and-systems/exploratory-testing-of-agents.md) |
| 4 Agents | Mutations test the tests around the model | a handful of hand mutations against the shipped tests | classify every survivor: missing test, dead code, equivalent | mutmut, Stryker | [mutation-checking](../practices/4-agents-and-systems/mutation-checking.md) |
| 5 Safety | Labs publish frameworks and system cards | a capability threshold with required safeguards | read the card's evaluation section; list what is not public | system cards | [frontier-safety-frameworks](../practices/5-safety-and-security/frontier-safety-frameworks.md) |
| 5 Safety | Red teaming is adversarial, automated and human | an attack corpus run nightly | turn each finding into a regression case | promptfoo red team, garak, PyRIT | [red-teaming](../practices/5-safety-and-security/red-teaming.md) |
| 5 Safety | Any text the model reads is an input | an instruction inside a retrieved note | boundary rules; sentinel checks; assert the behaviour, not the refusal wording | injection corpora | [prompt-injection](../practices/5-safety-and-security/prompt-injection.md) |
| 5 Safety | Guardrails are layers with different jobs | managed filter, classifier, prompt rule | binary suite every build; know which layer caught what | Bedrock Guardrails, NeMo, Llama Guard | [guardrails](../practices/5-safety-and-security/guardrails.md) |
| 5 Safety | An over-blocking guardrail is a defect | "my battle with this habit" blocked | must-not-block cases in the suite | the same suite | [false-positive-protection](../practices/5-safety-and-security/false-positive-protection.md) |
| 5 Safety | Some copy is verbatim by law; some keywords must work everywhere | STOP from a handoff state | send the keyword from every state; diff verbatim copy byte for byte | state-machine tests | [regulated-domain-checks](../practices/5-safety-and-security/regulated-domain-checks.md) |
| 6 Observability | GenAI spans carry model, tokens and content | an LLM span linked to the app trace | assert on spans in unit tests; route LLM spans separately | OpenTelemetry, Langfuse, Datadog | [genai-tracing](../practices/6-observability/genai-tracing.md) |
| 6 Observability | Production is the biggest eval set | 1 percent of conversations scored online | sample, score, alert on drift | LLM platforms | [online-evals-and-drift](../practices/6-observability/online-evals-and-drift.md) |
| 6 Observability | Content leaks through collectors and logs | span content in a log platform | redact before export; test with every PII class | collector processors | [redaction-in-telemetry](../practices/6-observability/redaction-in-telemetry.md) |
| 7 Lifecycle | Post-training stages are gated by evals | SFT, then preference tuning, then RL with verifiable rewards | read a model paper's evaluation section; know what each stage measures | model papers | [post-training-evals](../practices/7-training-and-lifecycle/post-training-evals.md) |
| 7 Lifecycle | A fine-tune must beat the base model and a prompt | three arms on one held-out set | hold out before you tune; compare all three arms | fine-tuning APIs | [fine-tuning-evals](../practices/7-training-and-lifecycle/fine-tuning-evals.md) |
| 7 Lifecycle | A model upgrade is a release | replay the golden set on the new version | distributions per version; pin versions; watch deprecations | inference profiles | [regression-on-upgrade](../practices/7-training-and-lifecycle/regression-on-upgrade.md) |
| 7 Lifecycle | Eval data leaks into training data | a rewritten test set scores lower | rolling sets; canary strings; date checks | contamination tools | [data-contamination](../practices/7-training-and-lifecycle/data-contamination.md) |
| 8 Governance | Agents propose, humans merge | a draft pull request from an agent | branch protection; review; consecutive green runs before trust | GitHub protections | [human-in-the-loop](../practices/8-governance/human-in-the-loop.md) |
| 8 Governance | A generated test is unvalidated until proven | ten local runs, two nightly passes | quarantine then graduate | CI | [ai-generated-tests](../practices/8-governance/ai-generated-tests.md) |
| 8 Governance | Autonomous QA agents need a charter | five draft PRs a day, no framework edits | write the charter; add a kill switch | agent definitions | [autonomous-qa-agents](../practices/8-governance/autonomous-qa-agents.md) |
| 8 Governance | Cards document models, systems and datasets | a system card's evaluation section | read one; write one for your own set | card templates | [model-and-system-cards](../practices/8-governance/model-and-system-cards.md) |
| 8 Governance | Standards ask for documented testing and oversight | a risk register mapped to a framework | map your practices to the framework's clauses | NIST, ISO, EU, OWASP | [standards-and-regulation](../practices/8-governance/standards-and-regulation.md) |
